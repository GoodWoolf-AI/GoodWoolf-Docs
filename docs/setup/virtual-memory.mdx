# Virtual Memory

Training large models can require more virtual memory than a machine has in RAM or VRAM. This page describes two ways to provide it: add swap directly on a host dedicated to training, or use GoodWoolf's Podman wrappers to give a container isolated CPU, memory, and swap resources. Follow the section that matches your setup.

## Host virtual memory

Use host swap when the machine is fully dedicated to training and you want the host itself to provide additional virtual memory. This affects every process on the host, so it is a good fit only for dedicated training machines.

Create a swap file. This example creates a 90G swap file at `/swapfile`:

```bash
sudo fallocate -l 90G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
```

On btrfs, replace the `fallocate` command with:

```bash
sudo btrfs filesystem mkswapfile --size 90g /swapfile
```

Enable the swap file immediately:

```bash
sudo swapon /swapfile
```

Make the swap file persistent by adding it to `/etc/fstab`:

```bash
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

Verify that the swap file is active:

```bash
swapon --show
free -h
```

After a reboot, the entry in `/etc/fstab` enables the swap file automatically.

## Container virtual memory

Use a container when you want to increase virtual resources in isolation from the host. GoodWoolf's `gw machine` and `gw container` commands are convenient wrappers around Podman. A Podman machine adds another isolation layer with its own swap space; a container limits CPU, memory, and swap for training workloads.

### Configure Podman helpers

Install `podman`, `gvproxy`, and `virtiofsd`. Add the Podman helper directories so Podman can find `gvproxy`:

```bash
cat << 'EOF' >> ~/.config/containers/containers.conf

[engine]
helper_binaries_dir = [
  "/usr/local/libexec/podman",
  "/usr/local/lib/podman",
  "/usr/libexec/podman",
  "/usr/lib/podman",
  "/usr/bin"
]
EOF
```

If `virtiofsd` is installed in `/usr/libexec`, add that directory to your shell path:

```bash
export PATH="$PATH:/usr/libexec"
```

GoodWoolf does not generate a helper config in the project directory. Podman reads the configuration from `~/.config/containers/containers.conf`.

### Create and manage a Podman machine

A Podman machine is optional, but it gives the container a separate virtual memory environment. Create the machine named `goodwoolf-machine`:

```bash
gw machine create --cpus 2 --ram-size 4 --disk-size 100 --swap-size 90
```

`gw machine create` initializes the machine but does not start it. Start it, open an SSH shell, stop it, or remove it with:

```bash
gw machine start
gw machine shell
gw machine stop
gw machine remove
```

| Option | Meaning | Default |
| --- | --- | --- |
| `--cpus` | Machine CPU count | Not passed when omitted |
| `--disk-size` | Machine disk size in GiB | Not passed when omitted |
| `--ram-size` | Machine memory in GiB | Not passed when omitted |
| `--swap-size` | Machine swap in GiB | Not passed when omitted |

Values are supplied in GiB. Python converts memory and swap to the MiB units expected by Podman. Omitted options are left out of the Podman command, so Podman's own defaults apply.

### Create and manage the container

Create the container named `goodwoolf` from `docker.io/library/ubuntu`:

```bash
gw container create --cpus 2 --ram-size 4 --disk-size 100 --swap-size 90
```

The current local directory is mapped to `/workspace` inside the container, so run this command from the project root when you want the project available at `/workspace`.

`gw container create` creates the container but does not start it. Start it, open a shell, stop it, or remove it with:

```bash
gw container start
gw container shell
gw container stop
gw container remove
```

`gw container shell` opens an interactive bash shell and starts the container if needed. Multiple shells can be opened from separate terminals.

| Option | Meaning | Default |
| --- | --- | --- |
| `--cpus` | Container CPU count | Not passed when omitted |
| `--disk-size` | Container disk size in GiB | Not passed when omitted |
| `--ram-size` | Container memory in GiB | Not passed when omitted |
| `--swap-size` | Container swap in GiB | Not passed when omitted |

As with `gw machine create`, values are supplied in GiB and omitted options are left out of the Podman command.
