# Virtual Memory

Training large models on commodity hardware relies on virtual memory to supplement available VRAM. Training can run directly on the host by increasing its virtual memory capacity. However, using a container is recommended to isolate training workloads from other host processes. The GoodWoolf CLI can create and manage this container.

For an additional layer of isolation, GoodWoolf also supports running a Podman machine, even on Linux systems where a machine is not normally required. A Podman machine provides an independent virtual memory environment with its own swap space, separating container swap from host swap. This separation helps protect host performance from the memory demands while allowing training workloads to take advantage of extended virtual memory.

## Prerequisites

Install these helpers before creating a machine:

- `podman`
- `gvproxy` on `PATH`
- `virtiofsd` on `PATH` or in `/usr/libexec`

Run:

```bash
gw machine check
```

This verifies the prerequisites and prints the resolved paths. `gw machine create` also writes `.podman-helpers.conf` in the current directory so Podman can find `gvproxy`.

## Machine commands

```bash
gw machine create --disk-size 100 --swap-size 50 --ram-size 8192
gw machine open
gw machine remove
```

`gw machine create` initializes the machine with `--swap 0`, starts it, then creates and enables `/var/swapfile` inside the machine. `gw machine open` starts the machine if needed and opens an SSH shell. `gw machine remove` removes the machine and the generated config.

| Option | Meaning | Default |
| --- | --- | --- |
| `--ram-size` | Machine memory in MiB | Required for `gw machine create` |
| `--disk-size` | Machine disk size in GiB | Required for `gw machine create` |
| `--swap-size` | Swap file size in GiB | Required for `gw machine create` |
| `--cpus` | Machine CPU count | `2` |
| `--machine-name` | Podman machine name | `goodwoolf-machine` |

## Container commands

```bash
gw container create --ram-size 8192 --swap-size 50
gw container start
gw container stop
gw container shell
gw container remove
```

`gw container create` applies the memory and swap limits to the container. `gw container shell` starts the container if needed and opens an interactive bash shell; multiple shells can be opened from separate terminals.

| Option | Meaning | Default |
| --- | --- | --- |
| `--ram-size` | Container memory in MiB | Required for `gw container create` |
| `--swap-size` | Container swap in GiB | Required for `gw container create` |
| `--machine-name` | Podman machine connection | `goodwoolf-machine` |
| `--container-name` | Container name | `goodwoolf` |
| `--image` | Container image | `docker.io/library/ubuntu:24.04` |
| `--host-dir` | Directory mounted from the host | Current directory |
| `--container-dir` | Mount point inside the container | `/workspace` |
